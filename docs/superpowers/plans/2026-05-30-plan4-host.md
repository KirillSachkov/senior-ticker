## 0. Тезис фазы

До этого плана каждый слой собран и протестирован изолированно, но **никто их не связывает** в
работающий процесс: нет production-реализаций `ITickIngestor`/`IMetricsSink`, нет `BackgroundService`,
нет конфига, нет Generic Host. План 4 — **единственный composition root**: DI, конфиг, Serilog,
оркестрация старта/останова, метрики. Результат — end-to-end `MockExchange → конвейер → Postgres`,
который штатно стартует (миграции → writers → коннекторы) и штатно гасится (коннекторы → дренаж →
выход) без потери буфера.

**Ключевой инсайт фазы (для видео):** двухфазный дренаж §5.4 **не требует ручного координатора** —
он выпадает из **LIFO-порядка** start/stop хостед-сервисов Generic Host. Регистрируем в порядке
`DbInit → Metrics → Pipeline → Connectors`; останов идёт в обратном порядке `Connectors → Pipeline →
Metrics → DbInit`. То есть коннекторы гаснут ПЕРВЫМИ (вход перекрыт), затем `PipelineHostedService.StopAsync`
делает `Input.Complete()` и ждёт естественный дренаж. Координация = порядок регистрации + один
`Complete()`, а не таймеры и флаги.

## 2. Поток старта и останова (ядро плана)

### 2.1. Порядок регистрации хостед-сервисов (= хореография §5.4)
```
AddHostedService<DatabaseInitializerHostedService>()  // (1) StartAsync АВАITS миграции → до writers (#10)
AddHostedService<MetricsBackgroundService>()          // (2) метрики (loop в фоне)
AddHostedService(PipelineHostedService singleton)     // (3) RunAsync(abort) — поднимает шарды+writers
AddHostedService<ConnectorHostedService>()            // (4) ПОСЛЕДНИЙ → останов ПЕРВЫМ
```
- **Старт (порядок регистрации, `ServicesStartConcurrently=false`):** DbInit *дожидается* миграций →
  Metrics → Pipeline (writers готовы принимать) → Connectors (начинают лить тики). Инвариант #10:
  схема готова до первого COPY.
- **Останов (обратный порядок, `ServicesStopConcurrently=false`):**
  1. `Connectors.StopAsync` — отменяется `stoppingToken` → `RunAsync` коннекторов ловит OCE, Polly v8
     не ретраит отмену (#6) → коннекторы выходят. **Вход перекрыт.**
  2. `Pipeline.StopAsync` — `Input.Complete()` → router завершает шарды → шарды флашат последний
     неполный батч → батч-канал завершается → writers дописывают COPY → `RunAsync` возвращается.
     Ограничено `DrainTimeoutSeconds`. **Буфер не потерян (#5).** (Metrics ещё тикает — видим дренаж.)
  3. `Metrics.StopAsync`, 4. `DbInit.StopAsync` (noop).

### 2.2. Два токена (§5.4)
- **host-stop** (`stoppingToken` коннекторов) — гасит **только коннекторы** (прекращаем reconnect).
- **abort** (внутренний CTS у `PipelineHostedService`) — НЕ дёргается при штатном дренаже. Конвейер
  гасит `Input.Complete()`, а не отмена. `abort.Cancel()` — лишь форс при превышении `DrainTimeoutSeconds`
  (тогда честно логируем «drain exceeded — возможна потеря буфера»).
- **`HostOptions.ShutdownTimeout = DrainTimeoutSeconds + 5s`** (дефолтные 5с малы для дренажа §5.4).
  Ставится явно в Program/extension из конфига.

### 2.3. Fail-fast (#C1 на уровне хоста)
`PipelineHostedService` вешает на `_run` continuation: если конвейер **зафолтился** (фатал sink'а —
`WriteLoopAsync` поднял исключение, не OCE), логируем `Critical` и зовём
`IHostApplicationLifetime.StopApplication()` → корректный нештатный останов, ненулевой exit. Без этого
мёртвый sink = тихий сталл (коннекторы льют в заблокированный канал) — ровно класс багов, против
которого вся спека.

## 3. Решения по проблемам ревью

### #7 — консистентный снимок метрик
`MetricsSink`: четыре **монотонных** `Interlocked`-счётчика (`received/deduped/written/dropped`).
`Snapshot()` читает все вместе (`Interlocked.Read`) и **не сбрасывает** — у ученика баг был в reset
части счётчиков, рассинхронизировавшем rate. `MetricsBackgroundService` держит предыдущий снимок и
логирует **дельты** + ключевую величину **gap = received − written** (успевают ли writers) +
**channel depth** (`IngestDepth`/`BatchDepth` — какой лейн лимитирует). Честный нюанс для защиты:
четыре `Interlocked.Read` не один атомарный снимок, но счётчики монотонны и считаем дельты — рваное
чтение максимум сдвинет один тик в соседнюю секунду, итоговые суммы не корраптятся (в отличие от
reset-десинка ученика).

**Осознанная девиация от §12 (защищаем явно, не молча сужаем):** спека §12 перечисляет набор
`in / parsed / deduped / written / dropped`. Эталон реализует **четыре** счётчика
`received / deduped / written / dropped`, где:
- `received` = тики, **принятые в конвейер** (после parse+validate, точка router'а), а не сырой
  socket-inflow. Именно эта величина участвует в ключевом SLI `gap = received − written` и в
  backpressure (полный ingest-канал тормозит именно принятые тики);
- `parsed` **свёрнут в `received`**, а parse-fail и validate-fail оба идут в `dropped` — на горячем
  пути коннектора (План 2) отдельный parse-счётчик дал бы разбивку причин отказа, но при 100/с это
  не оправдывает усложнение `IMetricsSink` и инструментацию каждого кадра. `gap`-инвариант полностью
  сохранён. Разбивка raw-inflow / parse-rate / parse-vs-validate переносится в **План 5** (нагрузка),
  где сырой входной поток и parse-success — реально измеряемые величины под бенчем.

> **Микро-правка в Processing (хирургически):** добавить в `TickPipeline` две read-only проперти
> `int IngestDepth => _ingest.Reader.Count;` и `int BatchDepth => _batches.Reader.Count;` — экспонирование
> глубины каналов для §12. Больше в Processing не трогаем.

### #9 — никаких debug-коннекторов в проде
1. **enabled-only:** `ConnectorFactory` строит только `Enabled==true`.
2. **wss-валидация на старте → fail boot:** `SeniorTickerOptionsValidator : IValidateOptions` +
   `.ValidateOnStart()`: каждый enabled-URL обязан быть `wss://`, либо `ws://` на **loopback**
   (`Uri.IsLoopback`). Иначе host не стартует (`OptionsValidationException`). Это одновременно кольцо 1
   (транспорт) и killer debug-коннектора: прод-`appsettings.json` имеет `Exchanges: []`, а
   `appsettings.Development.json` — mock-коннекторы на `ws://127.0.0.1` (loopback разрешён).
3. **defense-in-depth:** `ConnectorFactory` повторно валидирует URL при сборке (на случай конфигурации
   мимо validator'а).

### #10 — миграции до writers (оркестрация уже готового)
`DatabaseInitializerHostedService.StartAsync` **дожидается** `DatabaseInitializer.InitializeAsync`
(План 3, `MigrateAsync` через `IDbContextFactory`). Регистрируется первым → завершается до старта
`PipelineHostedService` (writers). `StopAsync` — noop.

### #5/#6 — оркестрация дренажа
Описано в §2. Код дренажа уже в `TickPipeline` (План 1) и Polly-политике (План 2); Host лишь связывает
порядок и таймауты.

## 4. Конфигурация (§14)

`appsettings.json` (prod-дефолты, **без секретов**):
```jsonc
{
  "Serilog": { "MinimumLevel": { "Default": "Information",
               "Override": { "Microsoft": "Warning", "System": "Warning" } },
               "WriteTo": [ { "Name": "Console" } ] },
  "Postgres": { "MaxWriterConnections": 8 },            // ConnectionStrings:Postgres — из env/user-secrets
  "Pipeline": { "ShardCount": 1, "WriterCount": 2, "IngestCapacity": 1000, "ShardCapacity": 1000,
                "BatchChannelCapacity": 8, "BatchMaxSize": 1000, "BatchMaxDelayMs": 100, "DedupWindowSeconds": 60 },
  "Shutdown": { "DrainTimeoutSeconds": 30 },
  "Metrics": { "IntervalSeconds": 1 },
  "Exchanges": []                                       // prod: реальные wss; пусто по умолчанию
}
```
`appsettings.Development.json` — три mock-коннектора (`ws://127.0.0.1:5000/{binance|kraken|csv}`,
`Enabled:true`). Запуск: `DOTNET_ENVIRONMENT=Development` + поднятый MockExchange.

**Секрет (§11):** строка подключения — `ConnectionStrings:Postgres` из **env** (`ConnectionStrings__Postgres`)
или **user-secrets** (dev, `AddUserSecrets(optional:true)`). В appsettings — только имена. Пусто/нет →
явный `InvalidOperationException` на старте (fail boot, не тихая неавторизованная коннекция).

**Решение про `Symbols[]` (анти-dead-config):** спека §14 упоминает `Symbols[]`, но наши коннекторы
к mock-эндпоинтам не подписываются по символам (mock сам стримит фиксированный символ). Класть в
конфиг поле, которое код игнорирует — ровно «dead config», за который штрафует No Vibecoding (урок
Плана 3 с мёртвым `MaxPoolSize`). **Поэтому `Symbols[]` НЕ добавляем**; per-symbol-подписка =
мультиплексирование (§10, growth path), YAGNI для single-process теста. Фиксируем явно в README.

## 5. Ключевые контракты кода (скелеты)

`ChannelTickIngestor` — `ValueTask IngestAsync(t,ct) => pipeline.Input.WriteAsync(t,ct);`
`MetricsSink` — `Interlocked.Add` на запись; `Snapshot()` = `Interlocked.Read` ×4 в `readonly record struct MetricsSnapshot`.
`TransportSecurity.ValidateWebSocketUrl(name,url)` — `wss` ok; `ws && IsLoopback` ok; иначе throw.
`PipelineHostedService` — `StartAsync`: `_run = pipeline.RunAsync(_abort.Token)` + fail-fast continuation;
`StopAsync`: `Input.Complete()` → `await _run.WaitAsync(drain, ct)`; `TimeoutException/OCE` → `_abort.Cancel()` + observe; в конце `if(_run.IsFaulted) await _run`.
`ConnectorHostedService` — `ExecuteAsync`: `Task.WhenAll(factory.CreateEnabled(opts.Exchanges).Select(c=>c.RunAsync(stoppingToken)))`, catch OCE при stop.
`MetricsBackgroundService` — `PeriodicTimer(interval, time)`; цикл `WaitForNextTickAsync(stoppingToken)`; лог дельт+gap+depth.

DI (`AddSeniorTicker`):
```
AddSerilog((sp,lc)=>lc.ReadFrom.Configuration(cfg).ReadFrom.Services(sp).Enrich.FromLogContext().WriteTo.Console());
AddSingleton(TimeProvider.System);
AddOptions<SeniorTickerOptions>().Bind(cfg).ValidateOnStart(); + IValidateOptions (wss).
Configure<HostOptions>(o => { o.ShutdownTimeout = drain+5s; o.ServicesStartConcurrently=false; o.ServicesStopConcurrently=false; });
AddSingleton<MetricsSink>(); AddSingleton<IMetricsSink>(sp=>sp.GetRequiredService<MetricsSink>());
AddSingleton(pipelineOptions); AddSingleton<TickPipeline>();
AddSingleton<ITickIngestor, ChannelTickIngestor>();
AddSingleton<ConnectorFactory>();
AddPostgresPersistence(new PostgresOptions{ ConnectionString = cfg.GetConnectionString("Postgres") ?? throw …, MaxWriterConnections = … });
// хостед-сервисы — в порядке §2.1
```

   - `TransportSecurity`: wss ok; ws-loopback ok; ws-публичный → throw; http → throw. → verify.

   - `ConnectorFactory`: Format→правильный парсер; `Enabled:false` исключён. → verify.
   - `PipelineConfig.ToOptions()`: маппинг Ms/Seconds → TimeSpan. → verify.

   - Поднять MockExchange (Kestrel, рандом-порт) + Postgres-контейнер.

   - `StopAsync` (штатный) → дренаж без ошибок, счётчик строк стабилен (нет рваной транзакции). → verify.
4. **Полный прогон:** все существующие 89 тестов + новые — зелёные, 0 warnings. → verify.

## 7. Чего НЕ делаем (scope guard)
- Не реализуем per-symbol-подписку/мультиплексирование (§10 growth path).
- Не трогаем код дренажа в `TickPipeline`/Polly — он готов (Планы 1–2), только оркеструем.
- Не добавляем advisory-lock для мульти-инстанс-миграций (§6.4 growth, отдельная заметка для Плана 5).
- Не добавляем `packages.lock.json`/`RestoreLockedMode` здесь — отдельный supply-chain пункт Плана 5.
- Единственная правка вне Host — две read-only проперти глубины каналов в `TickPipeline` (для #7).
